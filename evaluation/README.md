# Ручная проверка официальных фотографий

`manual_official_labels.tsv` — небольшая, намеренно неполная таблица: 17 подтверждённых товаров, один кадр с несколькими возможными целями (`ambiguous`) и один видимый товар, для которого карточка в текущем каталоге не найдена (`unknown`). Каждая строка привязана к SHA-256 исходного изображения и содержит видимое основание идентификации. Отсутствующая строка означает «ещё не проверено», а не ошибку модели.

Для новой метки нужно открыть **исходный снимок**, прочитать название/производителя/сорт/год с этикетки, сопоставить их с карточкой `df_2.csv`, затем записать хеш и доказательство. Нельзя брать за истину имя фото, его числовой префикс, первую выдачу модели или ближайшую похожую карточку. При нескольких бутылках без указания цели ставится `ambiguous`, а когда точной карточки нет — `unknown`; в обоих случаях `slug` пустой.

Эти 17 снимков выбраны вручную для первичной отладки. На них визуальный Top-1 составил 14/17, Top-5 — 16/17; с OCR Top-1 — 16/17, Top-5 — 16/17. Результат относится **только к этим фото**. Для сравнения новых вариантов нужно заранее выделить другие удержанные фото по сеансам съёмки и не выбирать коэффициенты по ним. Для вычисления результата с хешами и задержками выполните команду из корневого `README.md`.

`holdout_official_labels.tsv` содержит 23 фото, снятых в 12 календарных дней, которых нет среди 17 подтверждённых примеров первичной отладки. В нём 7 проверенных `slug`, 10 случаев без найденной точной карточки и 6 неоднозначных. Выбор по дням сделан **до** проверки OCR-версии ранжирования. Однако исходные визуальные предсказания для всех 100 фото уже просматривались при аудите, а проверенных случаев мало; результат на этом наборе будет только дополнительной проверкой, не независимой оценкой скрытого теста.


## Ручная проверка через Top-20

Перед присвоением статуса откройте исходный снимок и прочитайте этикетку целевой бутылки. Сначала найдите карточки по производителю, названию, серии, сорту и году в `df_2.csv`; учитывайте варианты написания. Затем получите визуальных кандидатов:

```bash
uv run --locked python -m scanner.review --image data/official_real_photos/ИМЯ_ФОТО.webp --top-k 20
```

Команда сохраняет в `data/evaluation/manual_review/` таблицу JSON с рангом, `slug`, названием, производителем, оценкой и хешами, а также лист сравнения исходного фото с 20 эталонами. Сравнивайте **текст этикетки, производителя, серию, сорт, цвет и год**, а не только дизайн. Близкий кандидат может быть другим вином той же серии, а правильная карточка может оказаться ниже 20-го места. Поэтому отсутствие в Top-20 само по себе не доказывает статус `unknown`; после него нужна текстовая проверка каталога. Не используйте ранг модели как метку без визуального подтверждения. Если правдоподобный `slug` есть, но равенство товара не доказано, ставьте `ambiguous` и фиксируйте кандидата в `evidence`. Для подтверждённого `slug` записывайте видимые признаки и SHA-256 фото.

Проверка двух примеров: на `1.73_06-09-2026_14-54-06.webp` центральная бутылка — Фанагория «ЛЕ КИФ», а в Top-20 нет Фанагории; поиск «КИФ»/`KIF` по каталогу также не дал карточки. На `96.77_24-08-2026_14-10-46.webp` видна Golubitskoe Estate Winery Series Red Blend; карточка `golubitskoe-estate-red-blend-kaberne-sovinon-krasnoe-suhoe-136` занимает 4-е место, но её эталон оформлен иначе. Это правдоподобная связь, а не доказанный точный `slug`, поэтому снимок помечен `ambiguous`.

Собственные магазинные фото размечены отдельно в `field_center_labels.tsv`; их проверка и ограничение по покрытию каталога описаны в [FIELD_PHOTOS.md](FIELD_PHOTOS.md). Они не входят ни в отладочную, ни в удержанную оценку официальных фотографий.

Проверка после фиксации разметки дала 7/7 Top-1 и Top-5 как для визуального baseline, так и для OCR-версии. Это подтверждает отсутствие регрессии на семи известных винах, но не прирост точности OCR на удержанном наборе. Включённый OCR изменил ответы некоторых фото со статусом `unknown`/`ambiguous`; их нельзя оценивать как правильные или ошибочные без официального правила выбора цели. Точный протокол запуска через `uv`, ревизия кода, хеши и задержки записаны в [RESULTS.md](RESULTS.md).
