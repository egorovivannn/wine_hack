На момент прогона в удержанной таблице было 11 фото со статусом `unknown` и 5 со статусом `ambiguous`; после дополнительной проверки Top-20 — 10 и 6 соответственно. В отладочной таблице по одному случаю каждого статуса. Они исключены из точности. Если на снимке несколько бутылок или точного товара нет в каталоге, без правила организаторов нельзя честно назвать один `slug` истинным. Контрольный скрипт организатора принял ответы HTTP API на трёх запросах; он не содержит правильных ответов.

## Повторение и проверка

После подготовки данных, загрузки весов и построения индекса по командам корневого `README.md`:

```bash
uv run --locked python -m scanner.evaluate \
  --images-dir data/official_real_photos \
  --labels evaluation/manual_official_labels.tsv \
  --output data/evaluation/uv_visual.jsonl
uv run --locked python -m scanner.evaluate \
  --images-dir data/official_real_photos \
  --labels evaluation/manual_official_labels.tsv \
  --output data/evaluation/uv_hybrid.jsonl --use-ocr
uv run --locked python -m scanner.score \
  --predictions data/evaluation/uv_hybrid.jsonl \
  --labels evaluation/holdout_official_labels.tsv
```

Предсказания в `data/evaluation/` не входят в Git. SHA-256 JSONL от этого прогона: визуальный — `638c22c77e89e289eff22a76618c42839acf491f86b63a82fb0842f9217a1cd6`, с OCR — `6517be6ad7c59c7becd592c8969353397c660a04e1cc0468f4baabc4a5738f82`. JSONL также содержит измеренное время каждого запроса, поэтому его побайтовый хеш и p50/p95 на другом запуске могут отличаться. В двух отдельно собранных окружениях Top-1 и весь Top-5 список совпали для всех 100 изображений в обоих вариантах.

Следующая проверка качества: договориться, какую бутылку считать целью на полочных кадрах; разметить собственные магазинные фото без просмотра выдачи модели; увеличить независимую подтверждённую выборку. Если ошибки на ней связаны с фоном или соседними бутылками, добавить выделение бутылки/этикетки и измерить прирост на этой же зафиксированной выборке.
