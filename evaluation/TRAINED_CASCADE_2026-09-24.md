## Сквозное сравнение на одинаковых реальных фото

Единица точности — точный `slug` центральной бутылки. Top‑1/Top‑5 считаются только на 59 `verified`; задержки — на всех 100 фото после загрузки моделей. Новая цепочка всегда использует Top‑20 исходного каталожного индекса как пул кандидатов; правильный `slug` присутствовал в этом пуле в 58/59 подтверждённых кадров.

В промежуточных строках измерена точность на кандидатах того же полного прогона; время отдельных стадий не замерялось. ## Воспроизведение

Выполнять из корня репозитория с `uv` и закреплённым `uv.lock`. Данные и веса кладутся в `data/`, где они игнорируются Git. Нужны `data/external/grain/Wine_Labels.zip` из GRAIN, `data/external/winesensed/metadata.zip` из Figshare (`https://ndownloader.figshare.com/files/41226051`), каталог и индекс согласно корневому README. Для старта YOLO26s поместить официальный `yolo26s.pt` в `data/models/training/yolo26s.pt` и сверить SHA выше.

```bash
uv sync --locked --group train --python /usr/bin/python3.12
uv run --locked --group train python -m detection.training.prepare_grain \
  --archive data/external/grain/Wine_Labels.zip --output data/external/grain/yolo_v2
uv run --locked --group train python -m detection.training.quick_train_detector \
  --data data/external/grain/yolo_v2/data.yaml \
  --output data/models/training/detector_yolo26s_v2 \
  --weights data/models/training/yolo26s.pt --epochs 12 --batch 4 --imgsz 640 --workers 4
uv run --locked python -m embedding.prepare_winesensed_sample \
  --metadata data/external/winesensed/metadata.zip \
  --output data/external/winesensed/sample_v2 --classes 300 --images-per-class 4
uv run --locked python -m embedding.train_label_head \
  --manifest data/external/winesensed/sample_v2/manifest.csv \
  --output data/models/training/label_head_v3 --epochs 30 --steps-per-epoch 50 --encode-batch 8
uv run --locked python -m embedding.train_top20_reranker \
  --manifest data/external/winesensed/sample_v2/manifest.csv \
  --head data/models/training/label_head_v3/best.pt \
  --output data/models/training/reranker_v4
uv run --locked --group train python -m evaluation.benchmark_trained_cascade \
  --detector data/models/training/detector_yolo26s_v2/weights/best.pt \
  --head data/models/training/label_head_v3/best.pt \
  --reranker data/models/training/reranker_v4/best.pt \
  --output data/evaluation/trained_cascade_v1.jsonl
```

Скрипты подготовки отвергают неверный MD5, конфликтные идентификаторы, изменение изображения и уже существующий выходной каталог. Для повторного запуска укажите новые выходные пути и соответствующие пути на следующих шагах. Подготовка GRAIN умеет быстро переразделить уже проверенные изображения через `--reuse`; итоговый корректный набор получен именно так после обнаружения пересечения дней съёмки в первом эксперименте.

Проверки после обучения: 21 unit-test прошёл; восстановленный API `/health` вернул 2 103 карточки; скрипт организатора `participant_test.sh` успешно получил три непустых `slug` (SHA-256 результата `38ff5b31f78cc692c26c7ebbb4c4bc8c7d019b23f4e20c996894535aeaa2a8c9`). Он не предоставляет правильные ответы, поэтому эти три запроса — проверка контракта, не точности.

## Ограничение вывода

Внешние WineSensed test-метрики измеряют поиск среди других вин и не переносятся напрямую на российский каталог. GRAIN test измеряет рамки этикеток, не выбор центральной бутылки и не `slug`. Официальные 59 меток ранее просматривались при проектировании baseline; независимого набора известных `slug` из новых магазинных сессий пока нет. Поэтому отрицательный сквозной результат надёжен как регрессия на зафиксированном наборе, но величина обобщения на скрытый тест неизвестна. Основной API сохранён на SigLIP2 + EasyOCR.
