# Интерфейс, функции после поиска и API

## Веб-интерфейс

Откройте `http://<адрес-машины>:18089/` в браузере и сфотографируйте бутылку или выберите фото из галереи. Интерфейс следует стилю vino-svoe.ru (бордовый #8F3D42, кремовый фон, заголовки Playfair Display) и рассчитан на телефон: съёмка камерой в одно нажатие, превью фото во время поиска, карточка с процентом совпадения, лента «Не то вино?» с ближайшими карточками и их сладостью, подсказки к блюдам, оценка звёздами и дневник. Картинки отдаются 512-пиксельными миниатюрами (`GET /v1/wines/{slug}/thumbnail`), а не многомегабайтными оригиналами. После распознавания карточка показывает три предложения к еде и позволяет проверить выбранное блюдо. `GET /v1/wines/{slug}/pairings?dish=fish` возвращает те же подсказки через API. Это детерминированные эвристики по категории, сладости в названии и доступному описанию, **не оценка сомелье и не обученная модель**. Подсказки не влияют на `slug` и контракт организатора. Для демонстрации можно использовать эталонное изображение из `data/competition_imgs`; официальный и собственный полочный holdout для этого прохода не применялся.

**Сравнение с вашим фото.** Когда сканер уверен (≥ 0,9), в углу фото бутылки из каталога — маленькое «Ваше фото», по нажатию оно увеличивается. Когда уверенность ниже 0,9, ваше фото показывается крупно в блоке «Не то вино?», прямо над вариантами той же серии, чтобы сверить название, сорт и сладость. В дневник сохраняется уменьшенная копия вашего фото (около 480 px, JPEG); если в браузере не хватает места, оценка сохраняется без фото.

## Функции после поиска

- **Похожие вина других виноделен** — `GET /v1/wines/{slug}/analogues?limit=4`. Тот же цвет и тип (тихое или игристое), другие производители, по одному вину на винодельню. Сходство складывается из общих сортов, сладости, региона и общих слов-нот в описаниях; каждое вино приходит с причинами («тот же сорт: рислинг», «тоже полусухое», «похожие ноты: яблоки, цветы»). Если сканер не уверен в ответе, блок называется «Если вашего вина нет в каталоге — похожие по стилю».
- **Цифровой сомелье** — `GET /v1/sommelier?dish=&color=&sweetness=&like=&offset=`. Три вопроса в формате чата: к чему (8 блюд или «без еды»), цвет (красное, белое, розовое, игристое) и сладость. Отвечает тремя винами разных виноделен с объяснением, «Ещё варианты» листает дальше. С карточки найденного вина сомелье подбирает вина «в похожем стиле» (`like=<slug>`).
- **Подсказки к блюдам**, **оценка звёздами и дневник** — как раньше, дневник хранится в `localStorage`.

Все рекомендации считаются офлайн по полям каталога за миллисекунды и не зависят от внешних API. В каталоге нет цен, продаж и рейтингов, поэтому подбор выражает сходство стиля и сочетаемость по описаниям, а не популярность или качество.

## API

Ответ `{"slug":"denisov_rubin_klaret_krasnaya_strelka"}`. Контракт организатора принимает одно multipart-поле `image` и всегда возвращает один непустой `slug`, даже при низкой уверенности. `POST /v1/predict` дополнительно возвращает карточку, `confidence` (доля первой карточки среди семи кандидатов: softmax итоговых оценок с температурой 0.02), `top5` с вероятностями, `verdict` (`confident` при `confidence ≥ 0.7`, иначе `check_alternatives` — подсказка интерфейсу показать варианты) и альтернативы. `confidence` не говорит, есть ли вино в каталоге: 18 из 35 фото вин вне каталога получают ≥0.7; `GET /v1/wines/{slug}` возвращает карточку. Страница сканера находится по `/`, здоровье сервиса — `/health`.

| Метод | Что возвращает |
|---|---|
| `POST /v1/eval/predict` | `{"slug": ...}` — контракт организатора |
| `POST /v1/predict` | карточка, `confidence`, `verdict`, `top5`, альтернативы |
| `GET /v1/wines/{slug}` | карточка вина |
| `GET /v1/wines/{slug}/thumbnail`, `/image` | миниатюра 512 px и оригинал эталона |
| `GET /v1/wines/{slug}/pairings?dish=` | подсказки к блюдам |
| `GET /v1/wines/{slug}/analogues?limit=` | похожие вина других виноделен |
| `GET /v1/sommelier?dish=&color=&sweetness=&like=&offset=` | подборка цифрового сомелье |
| `GET /health` | готовность сервиса |
