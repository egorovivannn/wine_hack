# Сканер российских вин

Локальный сервис получает фотографию бутылки и возвращает точный `slug` карточки из каталога конкурса. Веб-страница показывает найденное вино, визуально похожие варианты, подсказки к блюдам и сохраняет заметку в дневнике браузера. Текущая рабочая версия находится в ветке `audit-improvements`.

## Проверенное состояние

**Версия 27 сентября 2026 (рабочий API).** Поиск сравнивает три кропа фото с четырьмя видами каждого эталона, затем Qwen3.5-4B выбирает одну карточку из семи лучших кандидатов по надписям на этикетке. Пересмотренная ручная разметка [`evaluation/official_labels_v2.tsv`](evaluation/official_labels_v2.tsv) содержит 62 подтверждённых фото из 100, 35 вин вне каталога и 3 неоднозначных. На одной и той же разметке:

| Вариант | Top-1 | Top-5 | p50 / p95, RTX 3080 |
|---|---|---|---|
| прежний: 2 вида + EasyOCR | 53/62 | 61/62 | 698 / 1 054 мс |
| 3×4 вида, без проверки | 54/62 | 61/62 | 388 / 456 мс |
| 3×4 вида + Qwen3.5-4B, 5 кандидатов | 59/62 | 61/62 | 964 / 1 146 мс |
| 3×4 вида + Qwen3.5-4B, 9 кандидатов | 59/62 | 61/62 | 1 212 / 1 673 мс |
| 5 кандидатов + крупный центр фото вторым изображением | 59/62 | 61/62 | 1 444 / 1 705 мс |
| **3×4 вида + Qwen3.5-4B, 7 кандидатов (по умолчанию)** | **60/62** | **61/62** | **1 098 / 1 416 мс** |

На CPU (Ryzen 5 5600, 12 потоков, видеокарта скрыта; 12 подтверждённых фото — каждое пятое по имени): визуальный поиск — p50 1 200 мс, p95 1 307 мс, 11/12 Top-1, до 1,5 GiB RAM; с Qwen3.5-4B в float32 — p50 51,7 с, p95 63,7 с, 12/12, до 27,7 GiB RAM. Проверка на CPU не укладывается в 10-секундный таймаут скрипта организатора, поэтому без GPU сервис по умолчанию запускается без неё (`WINE_VERIFIER=0`).

Вес объединения и число кандидатов выбраны на этих же фото, поэтому 60/62 — оценка разработки, а не удержанного теста. Семь кандидатов вернули вино, стоявшее шестым; девять запутали модель на другой серии. Две оставшиеся ошибки: правильной карточки нет среди кандидатов (Литавщук Мерло) и близкая этикетка Фанагории; обе получают уверенность ниже 0.7, и интерфейс предлагает проверить варианты. Уверенность ≥0.9 выдана 52 раза, все верны.

**Пилот публичных фото 24 сентября 2026:** детерминированно выбраны 100 `slug` (50 из визуально близких пар, 50 случайных), проверены 191 страницы и 59 найденных изображений. Только одна пара прошла ручную проверку точного винтажа и независимости снимка; это студийное фото, не полка. Обучение, split и изменение API по такому материалу не проводились. На внешней validation объединение Frozen и CE Top-20 сохранило 310/317 Norwegian query в кандидатах против 308/317 и 306/317 по отдельности; объединение детекторного и центрального видов WineSensed — 848/864 против 844/864 у детектора. Это не тест российского каталога. [Протокол, манифесты, SHA и команды](evaluation/PUBLIC_PHOTO_PILOT_2026-09-24.md). Официальные и собственные магазинные holdout-фото в этом проходе не использовались.

**Новая внешняя итерация 24 сентября 2026:** на 2 284 классах WineSensed и 319 товарах Norwegian Grocery обучен компактный SigLIP2 adapter и два реранкера с группировкой похожих эталонов и полочных сцен. На независимом внешнем test WineSensed Top-1 изменился с 722/908 на 758/908; на Norwegian Grocery Top-1 visual reranker — 130/206 против 129/206 у замороженного энкодера, OCR-вариант — 131/206. Norwegian query использует размеченный bbox, поэтому это не end-to-end оценка магазина. Новые модели не включены в API: прирост на полках мал, Recall@20 снизился с 201/206 до 199/206, перенос на российские вина не доказан. Полный [отчёт, команды и SHA](evaluation/EXTERNAL_ITERATION_2026-09-24.md). Все 100 официальных и 13 собственных магазинных фото карантинированы для этой итерации и повторно не оценивались.

**Эксперимент 24 сентября 2026:** обучены детектор YOLO26s, адаптер эмбеддингов SigLIP2 и реранкер Top‑20 на внешних данных с отдельными train/val/test. На 59 вручную подтверждённых официальных фото согласованная с обучением полная цепочка дала 39/59 Top‑1 против 51/59 у текущего SigLIP2 + EasyOCR; поэтому API оставлен на проверенном варианте. Эти фото уже просматривались при разработке, а среди 13 собственных магазинных снимков нет подтверждённого `slug`. Команды, SHA checkpoint-ов, внешние test-метрики, задержки и ошибки — в [отчёте об обучении](evaluation/TRAINED_CASCADE_2026-09-24.md).

История до 27 сентября (прежний API):

- Индекс: 2 087 уникальных эталонных изображений, связанных с 2 098 карточками. Всего в `df_2.csv` 2 103 уникальных `slug`; у пяти нет пригодного эталона.
- Визуальная модель: `google/siglip2-base-patch16-384`, ревизия `f775b65a79762255128c981547af89addcfe0f88`. Для близких вариантов дополнительно используется EasyOCR 1.7.2. Веса обеих моделей и индекс проверяются по SHA-256 при запуске.
- На RTX 3080 (10 GiB) индекс построен за 169 секунд. Прогон через закреплённое `uv`-окружение на 100 официальных снимках с OCR: p50 698 мс, p95 1 054 мс; OCR понадобился на 51 кадре. Без OCR: p50 388 мс, p95 429 мс. Протокол и хеши — в [evaluation/RESULTS.md](evaluation/RESULTS.md).
- На **17 вручную отобранных и подтверждённых** снимках Top-1 = 16/17 с OCR против 14/17 без OCR. На семи подтверждённых фото других дней обе версии дали 7/7. Эти малые и смещённые выборки не являются оценкой скрытого набора; остальные официальные фото не имеют опубликованных ответов.
- Скрипт организатора `participant_test.sh` успешно обработал три контрольных запроса через HTTP.

## Воспроизведение на Ubuntu 24.04 с NVIDIA GPU

Требуются Python 3.12, [uv](https://docs.astral.sh/uv/getting-started/installation/), драйвер NVIDIA с поддержкой CUDA 12.8 (570+), GPU от 8 GiB, `7z`, около 15 GiB для архивов, эталонов и весов. `pyproject.toml` и `uv.lock` фиксируют зависимости для Linux x86-64: torch 2.11 (cu128), transformers 5.17, bitsandbytes 0.50. Команды ниже выполняются из корня репозитория. Исходные файлы положите в `data/source/Датасет.zip`, `data/source/official_real_photos.zip` и `data/field/real_photos.zip`. Последний архив содержит личные магазинные фото и нужен только для локальной проверки.

```bash
sudo apt-get install -y 7zip 7zip-rar jq
uv sync --locked --python /usr/bin/python3.12

uv run --locked python -m scanner.prepare
uv run --locked python -m scanner.reference_fixes
uv run --locked python -m scanner.model_fetch
uv run --locked python -m scanner.verifier download
uv run --locked python -m scanner.vision build --batch-size 16
uv run --locked python -m scanner.verifier thumbnails
uv run --locked python -m unittest scanner.test_catalog scanner.test_vision \
  scanner.test_ocr scanner.test_server scanner.test_evaluate scanner.test_score \
  scanner.test_pairing scanner.test_reference_fixes scanner.test_verifier -v
uv run --locked uvicorn scanner.server:app --host 127.0.0.1 --port 8088 --workers 1
```

Скрипт подготовки проверяет SHA-256 всех трёх исходных архивов и `df_2.csv`, извлекает ровно 2 087 нужных файлов из многотомного RAR, 100 официальных и 13 собственных фото. Он не использует порядок файлов в архиве или числовые префиксы имён фото как метки. При повторном запуске проверенные файлы не распаковываются заново. Только проверить подготовленные данные:

```bash
uv run --locked python -m scanner.prepare --verify-only
```

Все исходные архивы, фото, веса и индекс находятся в игнорируемом `data/`. `data/models/siglip2-base-patch16-384` занимает около 1,4 GiB, `data/models/qwen3.5-4b` — 8,8 GiB (на GPU загружается в 4 битах, около 3,3 GiB видеопамяти). Индекс по исправленному каталогу: `data/index/siglip2_multiview.npz` и `.json`; миниатюры эталонов для проверки — `data/index/verifier_thumbnails/`. `scanner.model_fetch` и `scanner.verifier download` загружают закреплённые ревизии и проверяют SHA-256; `scanner.vision build` отклоняет изменение эталонов относительно манифеста. Прежний EasyOCR-реранкер (`scanner.ocr download`) нужен только при `WINE_OCR=1`.

Переменные окружения сервиса:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WINE_VERIFIER` | `1` на GPU, `0` на CPU | `0` — только визуальный поиск, без Qwen; `1` на CPU — около минуты на фото |
| `WINE_OCR` | `0` | `1` — прежний EasyOCR-реранкер; действует только при `WINE_VERIFIER=0` |
| `WINE_DEVICE` | авто | `cpu` или `cuda` |
| `WINE_MANIFEST`, `WINE_INDEX` | исправленный каталог, `siglip2_multiview.npz` | другой каталог или индекс |
| `WINE_MODEL_DIR`, `WINE_VERIFIER_DIR`, `WINE_OCR_MODEL_DIR`, `WINE_IMAGES_DIR` | папки в `data/` | расположение весов и эталонов |

Оценка на размеченных официальных фото:

```bash
uv run --locked python -m scanner.evaluate --images-dir data/official_real_photos \
  --labels evaluation/official_labels_v2.tsv --output data/evaluation/v2_verifier.jsonl --use-verifier
```

`Dockerfile` содержит только окружение; `data/` готовится на хосте и монтируется. На проверочной машине образ пока не собирался:

```bash
docker build -t wine-scanner .
docker run --gpus all -p 8088:8088 -v "$PWD/data:/app/data" wine-scanner
```

## Исправленный каталог и веб-демо

[Аудит эталонов](evaluation/CATALOG_REFERENCE_AUDIT_2026-09-24.md) подтвердил три ошибочные связи карточки с изображением. Отдельный манифест исправляет только эти связи: 2 089 уникальных изображений для 2 098 карточек, девять общих эталонов и пять карточек без подтверждённого изображения. С 27 сентября сервис по умолчанию использует исправленный манифест; исходный сохранён. Остальные подозрительные связи перечислены в отчёте; точные замены для них не найдены. Хеши исходного манифеста, целевых изображений и полученного индекса проверяются при воспроизведении.

```bash
uv run --locked uvicorn scanner.server:app --host 0.0.0.0 --port 18089 --workers 1
```

Откройте `http://<адрес-машины>:18089/` в браузере и сфотографируйте бутылку или выберите фото из галереи. Интерфейс следует стилю vino-svoe.ru (бордовый #8F3D42, кремовый фон, заголовки Playfair Display) и рассчитан на телефон: съёмка камерой в одно нажатие, превью фото во время поиска, карточка с процентом совпадения, лента «Не то вино?» с ближайшими карточками и их сладостью, подсказки к блюдам, оценка звёздами и дневник. Картинки отдаются 512-пиксельными миниатюрами (`GET /v1/wines/{slug}/thumbnail`), а не многомегабайтными оригиналами. После распознавания карточка показывает три предложения к еде и позволяет проверить выбранное блюдо. `GET /v1/wines/{slug}/pairings?dish=fish` возвращает те же подсказки через API. Это детерминированные эвристики по категории, сладости в названии и доступному описанию, **не оценка сомелье и не обученная модель**. Подсказки не влияют на `slug` и контракт организатора. Для демонстрации можно использовать эталонное изображение из `data/competition_imgs`; официальный и собственный полочный holdout для этого прохода не применялся.

## API и проверка организатора

```bash
curl -F image=@data/official_real_photos/48.98_02-09-2026_18-34-15.webp \
  http://127.0.0.1:8088/v1/eval/predict
```

Ответ `{"slug":"denisov_rubin_klaret_krasnaya_strelka"}`. Контракт организатора принимает одно multipart-поле `image` и всегда возвращает один непустой `slug`, даже при низкой уверенности. `POST /v1/predict` дополнительно возвращает карточку, `confidence` (доля первой карточки среди семи кандидатов: softmax итоговых оценок с температурой 0.02), `top5` с вероятностями, `verdict` (`confident` при `confidence ≥ 0.7`, иначе `check_alternatives` — подсказка интерфейсу показать варианты) и альтернативы. `confidence` не говорит, есть ли вино в каталоге: 18 из 35 фото вин вне каталога получают ≥0.7; `GET /v1/wines/{slug}` возвращает карточку. Страница сканера находится по `/`, здоровье сервиса — `/health`.

```bash
cd data/source/eval
bash participant_test.sh --images-dir queries --manifest queries.tsv \
  --endpoint http://127.0.0.1:8088/v1/eval/predict \
  --output predictions.jsonl
```

Скрипт откажется перезаписать существующий `predictions.jsonl`: для повторной проверки укажите новый путь. В `data/source/eval/README.md` описан формат выдачи; правильные ответы для этих трёх фото организаторы не приложили.

## Внешняя оценка

Новая оценка и команды воспроизведения приведены в [отчёте внешней итерации](evaluation/EXTERNAL_ITERATION_2026-09-24.md). Полный gallery и одинаковая предобработка используются для каждого сравниваемого метода внутри одного split. ## Известные ограничения и следующий шаг

Все цифры на официальных фото получены на наборе, который использовался при разработке и подборе веса; независимой удержанной оценки у версии 27 сентября нет. Публичный поисковый пилот не дал достаточного числа точных пар для обучения или честной независимой оценки. Наиболее полезный следующий источник данных — новые собственные **размеченные** съёмки товаров, имеющихся в каталоге, с явной проверкой винтажа, производителя и `slug`, несколькими независимыми сеансами и отдельным final holdout. До появления такого набора API остаётся на baseline; официальный holdout этой итерацией не расходован.

Снимок должен показывать целевую бутылку ближе к центру. OCR исправил два различия внутри серий на отладочных снимках, но малый удержанный набор не доказывает прирост на скрытом тесте. 11 исходных эталонных файлов (девять после подтверждённых исправлений) привязаны сразу к двум `slug`, поэтому изображение не всегда позволяет выбрать точную карточку. Для 13 собственных магазинных фото цель задана как центральная бутылка; [ручная проверка](evaluation/FIELD_PHOTOS.md) не нашла ни одного подтверждённого совпадения с каталогом. Фотографии неизвестного вина и кадры с несколькими бутылками требуют отдельного правила оценки от организаторов. Подробности — в [ARCHITECTURE.md](ARCHITECTURE.md).
